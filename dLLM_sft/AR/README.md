# AR baselines

Full-parameter SFT of the autoregressive Qwen baselines with LlamaFactory. They use the same conda environment (`llamafactory_sdar`), data and training settings as the SDAR SFT runs of the same task, so that the RL comparison starts from SFT models trained in the same way.

```bash
bash dLLM_sft/AR/run_sft.sh alfworld-qwen3-8b   # Qwen3-8B-sfted-alfworld
bash dLLM_sft/AR/run_sft.sh webshop-qwen3-8b    # Qwen3-8B-sfted-webshop
bash dLLM_sft/AR/run_sft.sh webshop-qwen2.5-7b  # Qwen2.5-7B-Instruct-sfted-webshop
```

The models are written to `dLLM_sft/sfted_models/<name>`. The script refuses to overwrite an existing output. See the header of [run_sft.sh](./run_sft.sh) for the other options.

| File | Content |
| - | - |
| [configs/](./configs/) | LlamaFactory yamls, the counterparts of `dLLM_sft/SDAR/training/llama_factory_sdar/examples/train_full_sdar/` |
| [prepare_data.py](./prepare_data.py) | Converts `dLLM_sft/data/sdar/{alfworld,webshop}_sft.jsonl` into `work/*_sft_think.jsonl` (`<reason>` to `<think>`) |
| `work/` | Converted data, generated by the script and ignored by git |

## Settings

Identical to the SDAR yamls: ZeRO-2, 4 GPUs with per-device batch 1 (effective batch 4), learning rate 1e-5 with a constant schedule and 3% warmup, `neat_packing`, `truncate_mode: drop`, 16 preprocessing workers, and the same sequence length and epochs per task (ALFWorld 10240 tokens and 2 epochs; WebShop 20480 tokens and 1 epoch).

Differences from SDAR:

- Autoregressive causal-LM loss instead of the block-diffusion objective, and no `block_length` padding.
- `<reason>` / `</reason>` in prompts and responses are replaced with `<think>` / `</think>`.
- Qwen3 uses the `qwen3` template with thinking enabled. Qwen2.5-7B-Instruct uses the `qwen` template, which adds its default system prompt.

The models feed the Qwen RL scripts in `scripts/training/grpo_trainer/` through `MODEL_PATH`. `run_alfworld_sglang.sh` uses `Qwen3-8B-sfted-alfworld` by default.
